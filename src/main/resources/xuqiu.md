# 📌 完整需求文档：Java 8 百度地图地址查询与格式化工具

## 一、项目目标

开发一个基于 **Java 8 + Maven** 的**控制台程序**，实现以下完整流程：

1. 读取本地文本文件 `dizhi.txt`，每行一个待查询地址。
2. **模拟百度地图 PC 端真实搜索流程**，调用接口获取地址的详细信息。
3. 处理**一个地址对应多栋楼**的情况（如 `佳兆业中心A、B座`），拆分为多个子地址分别查询后合并区域。
4. 处理**一个地址查出多个候选 POI** 的情况（如 `香蜜楼B单元`），对候选做匹配度评分，选出最可能的那个。
5. 从返回结果中提取：**中心点坐标、多边形边界、名称、地址、类型**。
6. 将百度墨卡托坐标（BD-09MC）转换为 **BD-09 经纬度**。
7. 筛选出包含中心点的那个多边形作为该地址的范围边界。
8. 按指定格式输出为制表符分隔的 `output.txt`。
9. 生成一个 `map.html`，在百度地图上展示所有地址的中心点和多边形边界，便于人工校验。

---

## 二、输入文件 `dizhi.txt`

- **格式**：纯文本，**UTF-8 编码**，每行一个地址。
- **示例**：
  ```
  领航城·领秀花园-E栋
  福田区华强北街道上步中路1001号科技大厦
  坪洲站
  佳兆业中心A、B座
  统建楼办公楼1栋、2栋、3栋、4栋
  统建楼商住楼丁栋、丙栋、乙栋、甲栋
  飞扬时代大厦A、B座
  香蜜楼B单元
  ```
- **说明**：
   - 若某行为空或以 `#` 开头，跳过该行。
   - 地址不需要额外字段，`region_id`、`region_name`、`place_type` 均由程序自动生成或从接口返回结果中提取。

## 三、百度地图接口调用方式

根据抓包样例，百度地图 PC 端搜索涉及**两类请求**，必须按顺序执行。

### 3.1 同步请求 `usync`（POST，表单）

**作用**：上报本次搜索行为，百度服务端会返回 `sid` 和 `validate`，用于后续搜索请求鉴权。

**请求 URL**：
```
https://map.baidu.com/?newmap=1&reqflag=pcmap&biz=1&from=webmap&da_par=direct&pcevaname=pc4.1&qt=usync&mode=hsync&subkey=poihistory&t=【时间戳】&auth=【auth】&seckey=【seckey】&newfrom=zhuzhan_webmap
```

**请求方法**：`POST`

**请求头**：
```
Content-Type: application/x-www-form-urlencoded
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...
Referer: https://map.baidu.com/
```

**请求体（表单）**：
```
datas=[{"action":"add","detail":{"qt":"s","wd":"【地址】","ctime":"【时间戳】","platform":"3"},"ctime":"【时间戳】"}]
validate=【validate值，首次可留空或从页面获取】
```

**返回示例**：
```json
{
  "result": {"error": 0, "type": 2000},
  "tsync": {
    "upload": [{"action": "add", "ctime": "...", "cid": "...", "sid": "b77c...", "status": 100}],
    "download": [
      {"sid": "b77c...", "detail": "{\"qt\":\"s\",\"wd\":\"领秀花园e栋\",...}"},
      {"sid": "24a4...", "detail": "{\"qt\":\"s\",\"wd\":\"领航城·领秀花园-e栋\",...}"}
    ]
  }
}
```

**关键提取**：
- `tsync.upload[0].sid` → 本次搜索的 `sid`
- `result.error == 0` 表示同步成功

### 3.2 搜索请求 `qt=s`（GET）

**作用**：实际执行地址搜索，返回 POI 详情（中心点、多边形等）。

**请求 URL 模板**：
```
https://map.baidu.com/?newmap=1&reqflag=pcmap&biz=1&from=webmap&da_par=direct&pcevaname=pc4.1&qt=s&da_src=searchBox.button&wd=【地址URL编码】&c=340&src=0&wd2=&pn=0&sug=0&l=20&b=(12674865.534782156,2569320.130327998;12675003.272053305,2569496.9997071237)&from=webmap&biz_forward={"scaler":2,"styles":"pl"}&sug_forward=&auth=【auth】&seckey=【seckey】&device_ratio=2&tn=B_NORMAL_MAP&nn=0&u_loc=12702971,2562630&ie=utf-8&t=【时间戳】&newfrom=zhuzhan_webmap
```

**请求方法**：`GET`

**返回**：包含 `content` 数组的 JSON，字段提取方式见第五节。

### 3.3 参数说明

| 参数 | 说明 |
|---|---|
| `wd` | 待查询地址，需做 **URL 编码（UTF-8）** |
| `c` | 城市代码，深圳为 `340`，其他城市需调整 |
| `auth` | 鉴权参数，会过期，需从浏览器抓包获取 |
| `seckey` | 鉴权参数，会过期，需从浏览器抓包获取 |
| `t` | 当前毫秒时间戳 |
| `b` | 地图视野范围，可保留模板值 |
| `u_loc` | 当前定位坐标，可保留模板值 |
| `validate` | 同步请求返回的校验值，可留空 |

### 3.4 简化方案（推荐）

如果 `usync` 流程难以稳定复现，**可以只用第 3.2 步的 GET 搜索请求**，但需注意：

- `auth` 和 `seckey` 必须是从浏览器抓包获取的**最新有效值**。
- `t` 参数用当前时间戳（毫秒）。
- 如果返回 `result.error != 0` 或 `content` 为空，说明鉴权失效，需要重新抓包。
- 建议在 `AppConfig` 中把 `auth`、`seckey` 做成配置项，方便过期后替换。

### 3.5 鉴权参数获取

1. **浏览器抓包（推荐）**：
   - 打开百度地图，搜索一个地址。
   - F12 → Network → 筛选 `map.baidu.com`。
   - 找到 `qt=s` 的 GET 请求，复制 `auth` 和 `seckey`。
   - 找到 `qt=usync` 的 POST 请求，复制请求体和 `validate`（如有）。

2. **HAR 文件**：
   - 用浏览器导出 `map.baidu.com.har`，从中提取 `auth`、`seckey`、`validate`。

3. **配置项**：
   ```properties
   baidu.auth=【auth】
   baidu.seckey=【seckey】
   baidu.validate=【validate，可空】
   baidu.cityCode=340
   baidu.requestDelayMs=300
   ```

### 3.6 请求要求

- 必须设置请求头 `User-Agent`，否则可能被拒。
- 建议设置超时：连接超时 10s，读取超时 20s。
- 请求之间加 **200~500ms 延迟**，避免被限流。

## 四、多楼栋地址拆分处理

### 4.1 问题场景

输入地址中可能出现以下形式，一个地址对应多个楼栋或座：

| 输入地址 | 实际含义 |
|---|---|
| `佳兆业中心A、B座` | 佳兆业中心 A 座 + B 座 |
| `统建楼办公楼1栋、2栋、3栋、4栋` | 4 栋办公楼 |
| `统建楼商住楼丁栋、丙栋、乙栋、甲栋` | 4 栋商住楼 |
| `飞扬时代大厦A、B座` | 飞扬时代大厦 A 座 + B 座 |

**需求**：查询时不能只取其中一栋，而要把所有楼栋的区域**合并成一个整体范围**，中心点只保留一个，且该中心点应尽量落在合并后区域的合理位置（如几何中心或面积加权中心）。

### 4.2 处理流程

#### 步骤 1：地址拆分

在调用百度接口前，先判断地址是否包含多楼栋标识。识别规则：

- 包含 `、`、`，`、`,` 等分隔符，且分隔后的片段带有 `栋`、`座`、`楼`、`号楼` 等后缀。
- 包含 `A、B座`、`1栋、2栋` 这类模式。

**拆分策略**：

1. **提取公共前缀**：如 `佳兆业中心`、`统建楼办公楼`、`统建楼商住楼`、`飞扬时代大厦`。
2. **提取楼栋列表**：如 `["A座", "B座"]`、`["1栋", "2栋", "3栋", "4栋"]`。
3. **生成独立查询地址**：`公共前缀 + 楼栋`，例如：
   - `佳兆业中心A座`
   - `佳兆业中心B座`
   - `统建楼办公楼1栋`
   - `统建楼办公楼2栋`
   - ……

**若无法可靠拆分**，则退化为整串地址查询，取接口返回的第一个结果。

#### 步骤 2：逐个查询

对拆分出的每个独立地址，调用百度地图搜索接口，获取各自的**中心点**和**多边形边界**。每个子地址也要走第五节的“多结果匹配与择优”流程。

#### 步骤 3：合并区域

将所有楼栋的多边形合并为一个区域。合并方式：

- **方案 A（推荐）**：取所有多边形的**并集**，即外包多边形。若多边形不相邻，可用所有顶点的**凸包**作为合并范围。
- **方案 B（简单）**：取所有多边形的外接矩形并集，作为合并范围。精度较低，但实现简单。

**推荐方案 A**，用凸包（Convex Hull）算法合并所有顶点：

1. 收集所有楼栋多边形的所有顶点。
2. 计算这些顶点的凸包。
3. 凸包即为合并后的区域边界。

> 如果所有楼栋的多边形本身是相邻的，凸包能较好地覆盖整体范围；如果楼栋分散，凸包会偏大，此时可考虑用“并集多边形”算法（如 JTS 的 `union`）。

#### 步骤 4：确定唯一中心点

合并后只保留一个中心点，计算方式（按优先级）：

1. **几何中心**：凸包或合并多边形的几何中心（质心）。
2. **面积加权中心**：若各楼栋面积差异大，用面积加权平均。
3. **中心点校验**：若几何中心落在合并区域外（凹多边形可能发生），则取区域内部离几何中心最近的点。

**最终输出**：一个 `center_lonlat`，一个 `address`（合并后的多边形顶点数组）。

#### 步骤 5：输出

合并后的记录作为**一条**输出，`region_name` 使用原始地址（如 `佳兆业中心A、B座`），`place_type` 取第一个成功查询结果的类型。

### 4.3 示例

**输入**：
```
佳兆业中心A、B座
```

**拆分查询**：
- `佳兆业中心A座` → 中心点 `(x1, y1)`，多边形 `P1`
- `佳兆业中心B座` → 中心点 `(x2, y2)`，多边形 `P2`

**合并**：
- 合并多边形：`P1 ∪ P2` 的凸包 `P`
- 合并中心点：`P` 的几何中心 `(x, y)`

**输出**：
```
10124	佳兆业中心A、B座	{"lon":...,"lat":...}	[{"lon":...,"lat":...},...]	住宅楼栋
```

### 4.4 边界情况

| 情况 | 处理 |
|---|---|
| 拆分后部分楼栋查询失败 | 用成功的楼栋合并，记录日志；若全部失败，跳过该地址 |
| 拆分后只查到 1 栋 | 直接使用该栋的中心点和多边形 |
| 无法拆分 | 整串地址查询，取第一个结果 |
| 合并后多边形为空 | `address` 输出 `[]`，中心点用各楼栋中心点的平均值 |
| 楼栋多边形不相邻 | 用凸包合并，或改用 JTS `union` 得到精确并集 |

## 五、多结果匹配与择优

### 5.1 问题场景

输入 `香蜜楼B单元` 时，百度地图可能返回多个候选 POI，例如：

| 候选 | 名称 | 地址 | 可能问题 |
|---|---|---|---|
| 1 | 香蜜楼 | 福田区香蜜湖街道XX路 | 没有 B 单元 |
| 2 | 香蜜楼B单元 | 福田区香蜜湖街道XX路 | 完全匹配 |
| 3 | 香蜜二村B单元 | 福田区XX路 | 名称相似但不同小区 |
| 4 | 香蜜楼A单元 | 福田区香蜜湖街道XX路 | 楼栋号不对 |

**需求**：不能简单取 `content[0]`，而要对所有候选做**匹配度评分**，选出与输入地址最匹配的那个。

### 5.2 处理流程

#### 步骤 1：收集候选

从接口返回的 `content` 数组中取出**所有候选**（通常前 5~10 个），每个候选提取：

- `name`：POI 名称
- `poi_address` 或 `地址`：详细地址
- `std_tag` / `tag_info`：类型标签
- `diPointX/Y` 或 `navi_xy.diPoint`：中心点
- `bud_geom`：多边形（可能为空）
- `distance`（如有）：距离参考

#### 步骤 2：匹配度评分

对每个候选，按以下维度打分（满分 100）：

| 维度 | 权重 | 评分规则 |
|---|---|---|
| **名称完全匹配** | 40 | 候选 `name` 与输入地址完全一致 → 40；包含输入地址全部关键词 → 30；部分匹配 → 按匹配词数比例给分 |
| **地址关键词匹配** | 25 | 输入地址中的区、街道、路、小区名等关键词，在候选 `poi_address` 中出现 → 按命中比例给分 |
| **楼栋/单元匹配** | 20 | 输入含 `B单元`、`A座`、`1栋` 等，候选名称或地址中也含相同标识 → 20；含不同标识 → 0 |
| **类型匹配** | 10 | 输入推测为住宅，候选 `std_tag` 含“住宅”“楼栋” → 10；其他类型 → 0 |
| **多边形可用性** | 5 | 候选有 `bud_geom` 多边形 → 5；无 → 0 |

**总分 = 各维度得分之和**，取总分最高的候选。

#### 步骤 3：择优规则

- 若最高分**唯一**，直接选用。
- 若最高分**并列**，按以下顺序决胜：
   1. 有 `bud_geom` 多边形的优先。
   2. `distance` 更小的优先（若接口返回）。
   3. 名称更长的优先（通常更具体）。
   4. 仍并列则取 `content` 中顺序靠前的。
- 若所有候选得分都低于**阈值**（如 40 分），记录日志并跳过，或取第一个候选但标记“低置信度”。

#### 步骤 4：输出

选中的候选作为该地址的最终结果，输出格式不变。可在日志中打印评分明细，便于人工复核。

### 5.3 示例

**输入**：`香蜜楼B单元`

**候选与评分**：

| 候选 | 名称匹配 | 地址匹配 | 楼栋匹配 | 类型匹配 | 多边形 | 总分 |
|---|---|---|---|---|---|---|
| 香蜜楼 | 20 | 20 | 0 | 10 | 5 | 55 |
| 香蜜楼B单元 | 40 | 25 | 20 | 10 | 5 | **100** |
| 香蜜二村B单元 | 25 | 15 | 20 | 10 | 0 | 70 |
| 香蜜楼A单元 | 20 | 20 | 0 | 10 | 5 | 55 |

**结果**：选 `香蜜楼B单元`。

### 5.4 边界情况

| 情况 | 处理 |
|---|---|
| 接口只返回 1 个候选 | 直接使用，但仍做评分记录 |
| 所有候选无多边形 | 取评分最高者，`address` 输出 `[]` |
| 输入地址含多楼栋（如 `A、B座`） | 先拆分再查询，每个子地址分别做多结果择优，最后合并 |
| 最高分低于阈值 | 记录日志，标记“低置信度”，可配置是否跳过 |
| 候选名称完全相同但地址不同 | 用地址关键词匹配和 `distance` 决胜 |

## 六、JSON 解析与字段提取

取返回 JSON 的 `content` 数组，默认取 `content[0]`（若未启用多结果择优）。若 `content` 为空或长度为 0，记录日志并跳过该地址。

### 6.1 提取字段

| 目标字段 | 提取路径 | 说明 |
|---|---|---|
| `region_name` | `content[0].name` | 若为空，用输入地址兜底 |
| `poi_address` | `content[0].poi_address` 或 `content[0].地址` | 参考地址 |
| **中心点** | 优先 `content[0].ext.detail_info.navi_xy.diPoint.x/y`；其次 `content[0].diPointX/diPointY`；再次 `content[0].geo` 的第一个坐标 | 单位：米（BD-09MC） |
| **多边形** | `content[0].ext.detail_info.guoke_geo_bud.bud_geom` | 字符串，包含多个 `POLYGON ((x y, ...))` |
| `place_type` | 优先 `content[0].std_tag`，其次 `content[0].tag_info` 中的 `show_tag` | 若都为空，填“未知” |

### 6.2 `bud_geom` 格式说明

`bud_geom` 是字符串，包含多个多边形，格式类似：
```
POLYGON ((x1 y1, x2 y2, ..., x1 y1));POLYGON ((x1 y1, ...))
```
需要用正则或字符串解析，提取出每个多边形的坐标点列表。

## 七、坐标转换

百度地图接口返回的坐标是 **BD-09MC 墨卡托坐标**（单位：米），需要转换为 **BD-09 经纬度**。

转换公式（Java 8 实现）：
```java
public static double[] mercatorToLngLat(double x, double y) {
    double lon = x / 20037508.34 * 180.0;
    double lat = y / 20037508.34 * 180.0;
    lat = 180.0 / Math.PI * (2 * Math.atan(Math.exp(lat * Math.PI / 180.0)) - Math.PI / 2.0);
    return new double[]{lon, lat};
}
```

- 中心点和多边形所有顶点都要转换。
- 经纬度保留 **14 位小数**。

## 八、多边形筛选逻辑

1. 从 `bud_geom` 中解析出所有多边形（每个多边形是一个坐标点列表，首尾闭合）。
2. 对每个多边形：
   - 先计算外接矩形（minX, maxX, minY, maxY）。
   - 若中心点不在外接矩形内，直接排除。
   - 若在外接矩形内，用**射线法**判断点是否在多边形内部。
3. 选择**包含中心点的多边形**作为该地址的范围边界。
4. 若没有多边形包含中心点，则：
   - 优先取**面积最大**的多边形；
   - 若面积相同，取第一个。
5. 若 `bud_geom` 为空，则 `address` 字段输出空数组 `[]`。

射线法参考实现：
```java
public static boolean isPointInPolygon(double px, double py, List<double[]> polygon) {
    boolean inside = false;
    int n = polygon.size();
    for (int i = 0, j = n - 1; i < n; j = i++) {
        double xi = polygon.get(i)[0], yi = polygon.get(i)[1];
        double xj = polygon.get(j)[0], yj = polygon.get(j)[1];
        boolean intersect = ((yi > py) != (yj > py))
                && (px < (xj - xi) * (py - yi) / (yj - yi) + xi);
        if (intersect) inside = !inside;
    }
    return inside;
}
```

## 九、输出格式

### 9.1 `output.txt`

- **制表符分隔**，每行一个地址，字段顺序：
  ```
  region_id	region_name	center_lonlat	address	place_type
  ```
- **字段说明**：
   - `region_id`：从 `10124` 开始自增（可配置起始值）。
   - `region_name`：接口返回的 `name`，若为空用输入地址。
   - `center_lonlat`：格式 `{"lon":113.87715805983,"lat":22.575164191054}`
   - `address`：格式 `[{"lon":...,"lat":...},{"lon":...,"lat":...},...]`，多边形顶点闭合。
   - `place_type`：接口返回的类型，若为空填“未知”。
- **示例**：
  ```
  10124	领航城·领秀花园-E栋	{"lon":113.83123456789,"lat":22.62123456789}	[{"lon":113.83123456789,"lat":22.62123456789},{"lon":113.83133456789,"lat":22.62133456789}]	住宅楼栋
  ```

### 9.2 控制台输出

- 每处理完一个地址，打印一行进度：`[成功] 领航城·领秀花园-E栋 -> 113.831234, 22.621234`
- 失败时打印：`[失败] 地址xxx -> 原因`
- 多结果择优时打印候选评分明细。

## 十三、处理流程总览

```
读取 dizhi.txt
  ↓
判断是否多楼栋地址
  ↓ 是
拆分为多个独立地址
  ↓
逐个调用百度接口
  ↓

  ↓

  ↓

  ↓

  ↓

  ↓

  ↓ 否（单楼栋）
直接查询，走多结果择优，输出一条记录
  ↓
生成 output.txt 和 map.html
```
